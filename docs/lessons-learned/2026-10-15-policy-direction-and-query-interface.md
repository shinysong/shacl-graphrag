# 2026-10-15 — 공개 정책의 관계 방향과 조회 인터페이스

## Context

LLM이 금융·제조업 질문을 해석하고 SPARQL을 작성하며 온톨로지 검증 도구를 선택하는 개발 실험을 구현했다. 실행 코드 검사와 독립 검토를 마친 뒤 실제 모델 호출을 시작했다.

## Incident

제조업 영향 탐색의 공개 정책에는 `part_of`를 역방향으로 탐색한다는 문장이 들어갔다. 실제 데이터에서는 부품에서 상위 조립체로 향하는 `part_of`를 정방향으로, 제품에서 조립체를 가리키는 `contains`를 역방향으로 따라가야 한다. 실행 중 발견했고 동결한 입력을 바꾸거나 결과를 덮어쓰지 않았다. 이 정책이 적용된 세 사례는 모델 성능 비교의 해석에 제약이 있다.

모델이 문자열 ID를 URI로 조회하거나 선언하지 않은 prefix를 사용하는 오류도 관찰했다. 문법 오류와 빈 조회 결과는 다르며 둘 다 원천의 정보 부재로 처리하면 안 된다. 테스트 통과는 이런 모델 동작이나 업무 정책의 올바름을 보증하지 않는다.

## Lesson

공개 정책의 자연어 설명을 실제 관계 방향·속성·예제 레코드와 대조해야 한다. 코드와 채점기가 같은 잘못된 설명을 공유하면 검사 통과만으로는 발견하기 어렵다.

질의 생성이 연구의 핵심이 아니라면 자유 SPARQL과 구조화 조회를 별도 조건으로 두어 문법 작성의 부담을 분리한다. 모델이 역할과 필터를 잘못 선택할 가능성은 그대로 남겨서 의미 해석을 평가한다.

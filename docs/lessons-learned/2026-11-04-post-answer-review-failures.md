# 2026-11-04 — 사후 검토의 실패와 비교 조건

## Context

같은 초안과 선택 근거를 대상으로 Python과 pySHACL의 참고용 보고서를 준비했다. 후속 모델 비교는 실행하지 않았다.

## Incident

- 초기에 두 엔진이 같은 입력 오류를 반환해도 결과가 같다는 검사만으로 통과할 여지가 있었다. 정상 완료와 예상한 입력 실패를 나누고 전체 실행 수를 남겼다.
- 수정 프롬프트가 요구하는 `revision_log`가 처음 출력 형식에 빠져 있었다. 독립 검토에서 발견해 형식을 수정하고 새 작업으로 검토했다.
- 잘못된 헤더 컨테이너를 단순 확인 불가로 처리하던 경로가 있었다. 입력 형식 실패와 근거 부족을 분리했다.
- 검토 요청이 동결된 뒤 다른 실행기를 추가했다. 연구 운영 도구가 전체 `scripts/`·`tests/` 해시를 확인하므로 기존 검토 제출이 거부됐다. 그때 셸 배치가 실패 뒤에도 단위 검사를 이어갔다. 해당 관측은 승인된 검사로 쓰지 않고 새 작업에서 검토와 검사를 다시 수행했다.
- 보고서 없는 자체 검토의 메시지 준비도 검사기를 호출하고 있었다. 검사기 실패가 대조군까지 막을 수 있어 두 경로를 분리했다.
- 후보 질문의 `x_init`에는 mm 좌표와 표본 번호라는 두 열이 대응했다. 기존 후보를 보존하고 새 버전에서 mm 열을 명시했다.

## Lesson

엔진 간 결과 일치는 정상 작동의 충분조건이 아니다. 정상 완료, 입력 형식 오류, 근거 부족, 실행 오류를 먼저 구분하고 항목별 결과를 비교한다. 질문과 평가 기준이 같은 필드를 가리키는지도 모델 호출 전에 확인한다.

검토 중에는 관련 없어 보이는 코드라도 바꾸지 않는다. 변경이 필요하면 이전 요청과 실패 기록을 보존하고 새 검토를 만든다. 선행 승인이 필요한 셸 배치는 실패 시 바로 멈추게 한다.

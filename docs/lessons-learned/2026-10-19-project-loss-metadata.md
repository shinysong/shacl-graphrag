# 2026-10-19 — 프로젝트 복원과 자료 누락 표시

## Context

연결 설정을 저장하고 다시 불러오는 화면을 검증했다. 원본 행뿐 아니라 출처 메타데이터도 판정에 쓰이므로 프로젝트 백업에서 어떤 필드를 남기는지 함께 확인했다.

## Incident

프로젝트 JSON을 가져오면 내보내기와 같은 허용 필드 목록으로 출처 정보를 정리한다. 이 목록에 `redacted`가 없어 일부가 가려졌다는 표시가 사라지는 경로를 코드에서 발견했다. 표시가 사라진 뒤 사용자가 참조 범위를 확인하면, 표 연결 검사는 불완전한 자료를 완전한 것으로 취급할 수 있었다. 수정 전 실패 테스트를 실행한 기록은 없다.

`redacted`를 보존하도록 수정했고 JSON·ZIP 백업과 복원, 원본 유지, 연결 검사 보류를 포함한 관련 테스트 57개가 통과했다. 참조 범위에 대한 `complete` 선언은 자동 복원하지 않는다. [검증 기록](../experiments/records/20261019-linkage-provenance-roundtrip.json)

일반 참조 규칙에도 같은 표시를 반영했다. 일부만 있는 참조표에서 값을 못 찾으면 위반 대신 확인 불가로 처리하고 실제로 보이는 값의 목록 소속 판정은 통과로 유지한다. 최초 검사에서는 결과 목록의 순서를 가정한 새 테스트 8개가 실패했다. 행 번호별 판정으로 비교하도록 고친 뒤 관련 테스트 65개가 통과했다. 두 실행과 실패 원인을 모두 보존했다. [검증 기록](../experiments/records/20261019-reference-redaction.json)

설정 복원 브라우저 검사에서는 원본 프로젝트와 가져온 프로젝트의 해시가 같을 것이라고 가정해 실패했다. 해시에 출처 정보가 포함되므로 가져오기 과정의 메타데이터 정리도 차이를 만든다. 화면에서 저장한 설정을 같은 자료에 다시 적용하는 경로를 따로 검사했고 자료 변경 경고와 검토 확인 초기화를 확인했다. [검증 기록](../experiments/records/20261019-linkage-config-browser.json)

## Lesson

자료 누락 표시는 백업·복원·검사까지 이어지는 판단 근거다. 단순한 부가 정보로 취급해 제거하지 말고 복원 후에도 같은 보류 조건이 유지되는지 검사한다.

해시 차이를 곧바로 행 값의 변경으로 해석하지 않는다. 결과 비교는 반환 순서가 아니라 행 식별자로 수행한다. 현재 자료에서 값이 보인다는 판단과 전체 자료에서 유일하게 연결된다는 판단도 구분한다.

## Follow-up

- [x] JSON·ZIP에서 `redacted` 보존과 참조 범위 재확인 유지.
- [x] 일반 참조 규칙에서 가려진 자료의 미발견 값을 확인 불가로 처리.
- [x] 설정 복원 안내에 데이터와 출처 정보의 차이를 명시.
- [ ] 이후 커넥터를 추가할 때 누락·잘림 표시의 저장 및 복원 검사를 함께 추가.

위 결과는 소프트웨어 회귀 검사다. 숨겨진 원본 누락을 탐지하거나 RDF·SHACL의 우월성을 입증한 실험은 아니다.

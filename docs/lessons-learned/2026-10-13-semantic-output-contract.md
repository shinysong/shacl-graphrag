# 2026-10-13 — 의미 판단과 응답 형식 오류의 분리

## Context

질문에 맞는 관계와 유효 시점을 고르는 합성 개발 실험을 추가했다. 앞선 고정 계약 검사와 구분하고 코드·SHACL·LLM에 동일한 근거를 제공했다.

## Incident

첫 구현은 의미상 부적절한 인용을 실행기에서 오류로 처리했다. 이대로라면 측정하려던 모델의 의미 판단 실패를 관찰하기 어렵다. 유료 실행 전에 이를 수정해 모델 출력을 보존하고 평가 단계에서 근거의 적합성과 지지 여부를 별도로 채점했다.

첫 실제 실행은 기존 모델 실행기의 중첩 JSON 문자열 형식을 재사용했다. 모델은 내부 값을 문자열 대신 JSON 객체로 반환했고 LLM 60행이 모두 형식 오류로 남았다. 응답 내용의 의미와 출력 계약 준수는 다른 문제다. 이 결과를 의미 판단 오답으로 해석하지 않았다.

두 번째 버전에서는 출력 계약을 단순한 JSON으로 바꿨다. 기존 실행을 수정하지 않고 새 코드 검토와 테스트를 거쳐 별도 실행으로 기록했다. 질문·근거·판단 기준은 유지했다.

## Lesson

실험 대상의 오류를 실행기가 몰래 고치거나 제거하지 않아야 한다. 의미상 틀린 답, JSON 형식 오류, HTTP 실패, 비용 확인 불가를 따로 기록한다. 형식을 지나치게 복잡하게 만들면 측정하려던 능력 대신 직렬화 준수만 평가하게 된다.

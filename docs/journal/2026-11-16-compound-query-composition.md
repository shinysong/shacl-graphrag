# 복합 질문의 조회 조합과 답변 범위 비교

기존 실험은 쿼리 선택과 목록 크기 비교에 머물렀다. 이번에는 원문 질문에서 시작해 LLM의 요구 분해, 조회 연결 계획, 실제 그래프 조회, 최종 답변까지 실행했다. 익숙한 합성 공장 자료에 새로 작성한 복합 질문 4건을 사용했다. 독립 벤치마크나 새로운 도메인 검증은 아니다.

## 세 조건과 공통 입력

A는 전체 쿼리 계약 6개, B는 요구별 BM25 상위 3개를 합친 목록을 보고 LLM이 조회 계획을 작성한다. C는 B의 같은 계획에 입력 종류·연결 검사와 미해결 요구 보고서를 추가한다. 계약의 설명·입출력·지원 범위는 공통이다. C가 다른 쿼리를 대신 선택하거나 추가 자료를 찾지는 않는다. 검색 목록은 세 질문에서 5개, 한 질문에서 6개여서 전체 목록과 차이가 작았다.

```text
원문 질문 → 공통 LLM 요구 분해
              ├ 전체 계약 → LLM 연결 계획 → 조회 → 최종 답변 A
              └ 검색 계약 → LLM 연결 계획 → 조회 → 최종 답변 B
                              └ 같은 계획 점검 → 조회·보고서 → 최종 답변 C
저장 결과 → 별도 원문 요구·근거·답변 검토
```

질문 분해는 조건 간 공유한다. 분해 능력의 조건별 차이를 비교하지 않으며, 이후 선택·조합과 점검 절차를 비교한다. 실행 중 정답이나 평가용 요구 목록을 제공하지 않았다. 원문의 요구가 분해 단계에서 빠졌는지는 사후 독립 검토에서 확인했다. C의 보고서도 모델이 선언한 요구를 대상으로 하므로 원문 의미를 완전히 이해했다는 보증은 아니다.

## 실제 조회 연결

대표 질문은 M02 중단의 영향 주문, 대체 설비 후보, 후보 자격의 적용 가능성, 납기 판단을 함께 요구했다. LLM이 영향 주문 조회 결과를 후보 조회에 연결하고 주문별 제품·능력 조건을 유지해 자격 기록을 조회했다. 이 질문은 조건마다 실제 조회 9회를 수행했다. 후보라는 이유만으로 설비 운전이나 납기를 승인하지 않는다.

M03 질문에서는 선택한 자료의 영향 주문 조회가 빈 결과였다. 뒤의 후보·자격 조회를 진행할 입력이 없어 미해결로 남았다. 선택한 자료에서 찾지 못한 것과 전체 원천에 주문이 없다는 주장은 다르다. O18 질문은 배정 설비를 찾은 뒤 전체·현재·만료 자격을 구분해 조회했다. 이 자료의 M02 자격 기록은 없으며 과거 다른 자료의 만료 기록을 가져와 보충하지 않았다.

## 실행 결과와 답변 검토

| 항목 | 관측 결과 |
| --- | ---: |
| 복합 질문 | 4건 |
| 최종 답변 | 12개 |
| LLM 호출 | 24회 |
| 실제 RDFLib 고정 쿼리 조회 | 57회 |
| 조회 호출 실패 | 0회 |
| C의 연결 차단 | 0건 |
| API 보고 비용 | USD 0.2782440 |
| 실패에도 반환하지 않는 비용 예약 | USD 2.1429330 |

모델은 google/gemini-4-hydrogen, 제공자는 Google AI Studio이며 temperature 0으로 실행했다. 처음 두 호출 뒤 JSON 코드펜스 처리에서 중단됐다. 원래 실패를 보존하고 코드펜스만 해제하는 처리를 검토한 뒤, 저장된 두 응답을 그대로 재사용했다. 추가 22회로 마쳤으며 같은 유료 호출을 반복하지 않았다. 처음부터 오류 없이 완료한 실험으로 보고하지 않는다. 실행 권한은 닫았고 미확정 비용은 없다.

독립 검토자 두 명이 조건명을 가린 답변을 원문 질문·실제 조회 근거와 대조했다. 원문 요구 16개는 모두 모델의 분해에 포함됐다고 판단했다. 각 검토자의 요구별 평가 64개와 인용 구절을 보존했으며, 인용 128개가 실제 저장 문구와 일치하는지 확인했다. 이는 정답률 100%를 뜻하지 않는다.

두 검토자 모두 명백한 오류를 확정하지 않았지만 평가가 다른 항목 4개가 남았다. O18의 자격 이력 답변 세 개는 전체 이력을 보장할 수 없다는 이유로 부분 충족이라는 평가와, 선택 자료의 한계를 밝혔으므로 근거가 있다는 평가로 갈렸다. C 답변의 가용성 표현 한 곳도 기록상 사용 불가와 일정·부하 미확인의 구분이 모호하다는 의견을 보존했다.

## 확인한 범위와 남은 한계

질문별로 세 조건의 조회 근거는 같았다. C가 차단한 연결도 없어 계약 점검이 근거 없는 단정이나 불필요한 보류를 줄였다는 효과는 확인하지 못했다. 이번에는 전체 6개 목록만으로도 필요한 조회를 구성했다. 검사기의 잘못된 연결 처리 테스트는 실제 모델 오류를 줄였다는 증거와 구분한다.

현재 성과는 LLM이 쿼리와 연결을 작성하는 원사이클, 주문별 근거 계보, 미해결 요구의 답변 반영을 실제로 관찰한 것이다. SHACL 고유의 우위, 전체 원천의 완전성, 유지보수 비용 절감은 측정하지 않았다. 이 결과만으로 인덱스를 더 복잡하게 만들 근거도 없다.

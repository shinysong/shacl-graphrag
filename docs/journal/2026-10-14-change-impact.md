# 변경 영향 분석과 도메인별 의미 조건

이번 연구에서는 질문에 답하는 정확도에 더해 변경 뒤 재검증할 판단의 범위까지 연구 목적에 포함했다. 부품을 교체했을 때 어떤 제품의 규격·인증을 다시 확인해야 하는지, 기업 관계가 바뀌었을 때 어떤 연결을 재검토해야 하는지가 대상이다. 영향 경로를 찾는 과정과 물리·재무 성능을 예측하는 시뮬레이션은 구분한다.

## 명시적 관계의 효과와 한계

제조업 통제 실험에서는 정상 원천에서 규칙 기반 JSON과 RDF가 모두 정확했다. 같은 의미와 정보를 주면 형식을 바꾸는 것만으로 정확도가 달라지지는 않았다. 반면 관계 종류나 매핑 자체를 틀리게 주면 두 방식 모두 틀린 완전성 주장을 했다.

따라서 최소 의미 모델의 역할을 관계·방향·조건을 공유하고 판단 경로를 드러내는 데 둔다. 원천의 진실성과 수집 완전성을 보장하는 기능까지 포함시키지 않는다. 결과를 읽는 사람에게 찾아낸 제품 목록뿐 아니라 포함·제외의 근거와 미확인 범위를 제공해야 한다.

## 도메인과 표현 방식의 분리

실제 자료에서 FHIR은 유형을 포함한 식별자와 참조 역할, Wikidata는 진술의 시점·순위·참조, GLEIF는 관계 종류·기간·보고 예외를 보존할 필요가 있었다. FIBO의 스키마와 GLEIF의 실제 법인 관계는 서로 다른 층위다. 온톨로지를 받았다는 사실만으로 실제 업무 데이터가 연결되지는 않는다.

제조업은 잠재적 영향 제품을 찾고 금융은 특정 종류·시점의 기업 관계를 확인하며 의료는 기록의 주체·참조 역할을 대조해야 한다. 하나의 탐색 규칙에서 명칭만 바꿔 이 세 도메인을 검증했다고 주장하지 않는다.

## 후속 실험과 안내서의 근거

다음에는 같은 개체와 자료를 반복해 숫자를 늘리기보다 도메인 고유의 판단 기준을 고정한다. 금융에서는 회계 연결·펀드 운용 관계를 구분하고 기간·예외를 포함한다. 의료에서는 공식 예시를 바탕으로 참조 역할과 환자 맥락의 충돌을 다루되 임상적 적합성을 판단하지 않는다. 문서는 조항·예외·유효 버전의 위치를 평가 기준으로 삼아 구조 추출과 의미 판단을 분리한다.

자료를 갖췄다는 전제도 단계별로 기록한다. 구문 파싱 완료, 식별자 정리 완료, 매핑 승인, 수집 범위 확인은 각각 별개의 전제다. 이를 숨기면 잘 관리된 합성 데이터에서 얻은 결과가 현장 데이터에도 그대로 적용되는 것처럼 보인다.

입문 자료의 각 사례에는 원본 예시, 필요한 전처리, 최소 관계·규칙, 실제 출력과 실패, 재확인 항목, 검증하지 않은 범위를 붙인다. 지금은 이 안내서를 완성한 단계가 아니라 재현 가능한 기초 자료와 연구 지도를 만든 단계다.

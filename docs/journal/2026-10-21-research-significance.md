# 코드 기반·표준 기반 비교의 연구 의의

작성일: 2026-10-21

이 문서는 기존 연구의 의의를 정리한 기록이다. 연구 방향이나 평가 프로토콜의 변경을 뜻하지 않는다.

## 연구 의의 문안

사용자가 기록을 요청한 문안을 그대로 보존한다.

> 본 연구는 동일한 정책과 제한된 추론 과제를 코드 기반 구현과 표준 기반 구현으로 비교하여, 특정 표현 방식만이 해당 기능을 구현할 수 있다는 전제에서 벗어나 각 접근의 구현 범위와 책임을 구체화한다. 자체 코드 방식에서는 규칙 실행과 결과 추적에 필요한 기능을 직접 구성했으며, 표준 기반 방식에서는 기존 표현 체계와 구현체를 활용했다. 이러한 구현 경험은 성능 비교를 넘어 기술 선택의 근거를 제공한다. 또한 코드 기반 비교 구현과 평가 도구는 표준 기반 기술을 도입하지 않는 환경에서도 재사용할 수 있는 출발점이 된다.

## 구현 책임과 지식 관리의 구분

실행 도구의 유지보수와 지식·정책의 유지보수는 구분한다. 자체 코드에서는 지원할 규칙의 표현 형식, 실행 로직, 근거 기록, 오류 보고와 테스트를 구성하고 관리해야 한다. 표준 기반 접근에서는 표준화된 표현과 기존 구현체를 활용한다. 다만 표준을 사용한다고 모든 근거 추적이나 운영 기능이 자동으로 제공되는 것은 아니다.

어느 접근에서든 분류와 관계가 업무에 맞는지, 규칙이 충돌하는지, 데이터가 정합적인지와 정의 변경이 어떤 영향을 주는지는 별도로 관리해야 한다. RDF는 데이터 표현, OWL은 의미 정의와 추론, SHACL은 제약 표현과 검증의 역할로 구분한다.

## 재사용 가능한 산출물과 해석 범위

코드 기반 비교 구현과 평가 도구도 연구 산출물이다. 표준 기반 기술을 채택하지 않는 환경에서 명시적 규칙, 판단 유보, 실패 기록과 결과 비교를 구현하는 출발점으로 활용할 수 있다. 현재 산출물은 실험용이며 재사용 가능한 라이브러리로 정리하려면 인터페이스·의존성·지원 범위의 문서화가 필요하다.

유지보수 시간이나 사람의 이해도는 직접 측정하지 않았다. 따라서 유지보수 비용의 우열을 입증했다고 주장하지 않는다. 구현 경험에서 확인한 책임의 차이와 향후 재사용 가능성을 연구의 의의로 기록한다. 소매 데이터의 정책 검증과 이전의 제한된 온톨로지 추론 비교는 서로 다른 실험이며 하나의 통합 성능 벤치마크로 해석하지 않는다.

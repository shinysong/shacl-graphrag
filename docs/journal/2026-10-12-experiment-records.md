# 2026-10-12 실험 명세와 기록 방식

상태: 완료

## 실험 기록 체계 도입 배경

호스트 설정은 갖춰졌지만 연구 질문을 실행 가능한 조건으로 나눈 명세와 실험 결과를 쌓을 장소가 없었다. 실행이 끝난 뒤에도 어떤 조건으로 무엇을 확인했는지 읽을 수 있도록 기록 방식을 먼저 정했다.

여러 실험과 오픈소스 작업을 모으는 lab을 염두에 두되 이번에는 SHACL GraphRAG 저장소의 GitHub Pages부터 시작한다. 문서 원본은 `docs/`에 둔다. GitHub에서도 읽을 수 있고 나중에 별도 lab에서 링크할 수 있다.

## 사전 점검 실험과 기록 방식 선정

사전 점검은 합성 RDF와 pySHACL로 진행한다. 정상 사례 2건과 제약 위반 사례 4건의 정답을 미리 정해 검증과 채점 경로를 확인한다. YAGO와 LLM 비교는 이 절차를 확인한 뒤 시작한다.

실행기는 요약과 환경 정보를 자동으로 남긴다. 사람이 쓰는 일지에는 결과의 의미와 다음 결정을 적는다. 원본 로그는 `runs/`, 공개용 기록은 `docs/experiments/records/`에 보관한다.

## 관찰과 다음 작업

첫 실행에서 정상 사례 2건과 위반 사례 4건 모두 기대값에 맞게 판정했다. 위반 위치와 종류도 일치했으며 실행 오류는 없었다. [첫 실행 기록](../experiments/records/20261012T070907787564Z-e0-674d84f2.md)에 입력 해시와 환경 정보를 남겼다.

사전 점검의 통과는 작은 예제에서 검증기가 기대대로 동작했다는 근거다. GraphRAG의 답변 품질이 좋아졌다는 판단에는 YAGO 슬라이스와 고정 질문을 사용한 후속 실험이 필요하다.

다음 작업은 YAGO 배포 파일의 라이선스와 용량을 확인하고 1단계 슬라이스의 범위를 정하는 것이다.

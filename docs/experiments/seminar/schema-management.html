        3. 필드가 없다는 말의 서로 다른 의미
        같은 원문에 표준의 필드 설명을 추가한 경우와 추가하지 않은 경우를 비교합니다. 추가한 것은 의미 정보이며, SHACL 보고서나 데이터베이스를 비교하는 실험은 아닙니다.
        설명문은 보존하지만 자동 정답 평가는 분류값과 응답 형식에 한정합니다. 두 조건 모두 표준에 대한 모델의 기존 지식 사용을 허용했습니다.
        

        4. 같은 초안의 자체 검토와 SHACL 검토
        두 조건 모두 같은 원문, 표준 설명, 원래 초안을 받습니다. SHACL 조건에만 계산된 검사 보고서를 추가합니다. P03 오류를 본 뒤 고른 세 개발 사례이며, 새 평가 표본은 아닙니다.
        공급된 SHACL 보고서
        검사 보고서는 정답이나 강제 거부 명령이 아닙니다. Python으로 같은 정책을 검사한 결과도 별도로 대조했습니다.
        확인 범위와 출처
        SHACL 없이 공유 Python 정책으로도 같은 의미를 구현할 수 있습니다. 이번에는 인간의 유지보수 시간, 관리 복잡성의 임계점, 실제 장애 예측, 외부 사실의 진위를 측정하지 않았습니다. 모든 질문은 원문을 살펴보고 만든 개발 사례입니다.
        이 페이지는 저장된 기록을 재생합니다. 모델 호출, Neptune 시작, 자료 수정은 하지 않습니다.

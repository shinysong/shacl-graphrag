# 자료 탐색을 포함한 운영 자료실 채팅 검증

2026-11-23 · 작성한 개발 사례 · Gemini 3.8 Flash · temperature 0

## 구현 범위

자료실 채팅에 저장소 개요, 파일·테이블, 컬럼, 제한된 예시 값, 검토 상태를 탐색하는 도구를 추가했다. 승인 전에도 허용된 원본 구조를 설명할 수 있지만 탐색 결과가 업무 조회 승인을 대신하지는 않는다. 등록 DB는 저장된 스키마와 표본을 사용하며 현재 DB를 새로 조회한 것처럼 설명하지 않는다. 승인한 업무 질의는 기존 실행 경로를 유지한다.

목록은 최대 5개, 필드 예시는 최대 3개씩 반환한다. LLM은 최대 3단계에 걸쳐 전체 8개 도구를 선택할 수 있으며 답변 생성을 포함해 최대 4회 호출한다. 생략 범위, 원본 위치와 해시, 자료 버전, 도구 실패를 저장한다. CSV와 DB의 채팅 배치를 통일하고 이전 실행 기록에는 불러온 건수와 실패 건수를 표시했다.

## 실제 실행 결과

| 실행 묶음 | 질문 수 | 실행 완료 | 확인한 내용 |
| --- | ---: | ---: | --- |
| 첫 검증 | 14 | 12 | 이커머스·제조·조직 자료, 승인 전후, 빈 파일, 많은 컬럼, 복합 질문, 미지원 요구 |
| 조회 선택 형식 보완 후 | 4 | 4 | 조직 자료 탐색 복구, 가능한 조회와 검토 상태 |
| 미해결 요구 처리 보완 후 | 2 | 2 | 조직 자료의 전체 행과 표본 구분, 빈 CSV의 컬럼과 행 구분 |
| 승인 범위 설명 보완 후 | 2 | 2 | 승인한 업무 질의가 없는 경우의 탐색, 주문 파일 검색·컬럼·예시 값 조회 |
| 조회 기능·검토 영향 안내 보완 후 | 2 | 2 | 재고 기록 조회와 주문 변경 판단의 차이, 검토 대기 정책과 관련 질문 |

24건은 독립적인 평가 표본이 아니다. 처음 사용한 질문을 다시 확인하는 개발 진단도 포함했다. 이전 실패를 새 결과로 덮어쓰지 않았다. 실행 완료는 답변 품질 통과를 뜻하지 않는다. 첫 14건의 수동 점검에서는 근거로 뒷받침된 답변 8건, 일부만 답한 경우 3건, 실패 3건으로 분류했다. 실패에는 응답을 만들지 못한 2건과 탐색 도구가 있는데도 사용하지 않은 1건이 포함된다.

원래 실패했던 “이 데이터가 무엇인지 설명해주세요”는 실제 탐색 근거 3개를 인용해 소스 10개와 필드 46개를 설명했다. 자료 개요와 재고를 함께 물은 질문은 저장된 S1 수량 0개와 요청 수량 2개를 비교했다. 조직 자료에서는 전체 12행과 저장된 표본 5행을 구분했고 빈 CSV는 컬럼 2개와 데이터 행 0개를 구분했다.

마지막 진단에서는 모델이 이전 확인 항목을 e1 근거로 답변 완료로 분류했고 원래 확인 항목도 기록에 남았다. 이는 한 사례의 모델 판단이다. 시스템은 답변의 참을 보증하지 않는다.

두 건의 추가 진단에서는 실제 조회 목록과 검토 대기 정책을 함께 확인했다. 재고 기록 대조는 가능한 기능으로, 주문 변경 판단은 별도의 정책 선행 요건을 확인하는 기능으로 설명했다. 넓은 질문은 도구 8개 한도에 도달해 미조회 범위를 남겼다. 기능 안내만 요청한 질문에 실제 실행까지 미해결 요구로 덧붙인 답변도 있었다. 두 건을 모두 답변 품질 통과로 세지는 않았다.

## 비용과 검증 범위

이번 작업의 실제 LLM 호출은 68회, 보고된 비용은 $0.19050675였다. 이 값은 작업 시작 이후의 증가분이며 전체 서비스 누적 비용과 구분한다. 예약액과 실패 원장은 따로 보존했다. 에이전트 검증은 사람의 하루 10회 한도를 차감하지 않았으며 총비용 제한과 종료 시각은 바꾸지 않았다.

최신 변경의 집중 검사에서는 테스트 74개와 하위 검사 21개가 통과했다. 자료실 검사 246개는 1개를 건너뛰고 성공했다. 독립 방법론·구현·제품 UX 리뷰와 1440px·375px 브라우저 확인을 수행했다. 소프트웨어 검사 통과를 일반적인 답변 정확도로 해석하지 않는다.

## 남은 한계

파일·컬럼 검색은 이름에 포함된 문자열을 찾는다. “주문 관련 자료” 진단은 orders.csv를 찾았지만 주문과 관련된 모든 파일을 의미적으로 탐색한 결과는 아니다. 모델 답변에는 내부 필드명이나 긴 주의 문구가 남을 수 있고 일부 질문에서는 이미 답한 내용을 미해결로 남겼다. 승인 범위를 잘못 해석한 기존 답변도 보존했다.

한 모델과 소규모 작성 자료에서 확인한 결과다. 대규모 DB, 모든 정책 문서의 적용성, 임의 분야의 질문 정확도나 실제 업무 실행을 검증한 결과가 아니다. 사용자 안내의 질문 예시로 시작하고 답변에 연결된 자료 버전과 근거를 확인하는 용도로 사용한다.

## 직접 확인할 질문

쇼핑몰 운영 자료를 선택한 뒤 다음 질문을 입력할 수 있다. 각 답변에서 자료 버전과 인용된 도구 결과를 함께 확인한다.

- 이 데이터가 무엇인지 설명해주세요.
- 주문 관련 자료의 구성과 주요 컬럼, 예시 값을 알려줘.
- 자료 개요를 설명하고 S1 상품 2개의 재고가 기록상 충분한지 확인해줘.
- 재고 기록 확인과 주문 변경 판단은 각각 어떤 검토가 필요한가요?

검증용으로 만든 저장소 5개는 보관 처리했다. 원본 자료·버전·실행 결과·비용 기록은 삭제하지 않았다.

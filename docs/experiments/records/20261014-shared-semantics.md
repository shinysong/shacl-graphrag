# 2026-10-14 — 공통 의미 규칙과 업무 간 변경 실행

실행 `20261014T063154Z-shared-semantics`에서 예정된 12,288행을 모두 생성했다. 실행 오류와 미실행 행은 0개다. [실험계획](../shared-semantics-study.md)에 따라 합성 공급 국가 조회·지역 제한 점검·대체 공급자 추천을 비교했다. 유료 모델 API와 DB 서버는 사용하지 않았다.

## 정상 갱신과 오류 주입 결과

아래는 결정·값이 현재 원천과 의도한 업무 조건에서 벗어난 횟수다. 각 칸의 분모는 768행이며 근거 내용의 불일치와 구분한다.

| 비교군 | 정상 갱신 | 설정 사본 지연 | 추출본 지연 | 공통 매핑 오류 |
| --- | ---: | ---: | ---: | ---: |
| 업무별 JSON | 0 | 32 | 0 | 260 |
| 공통 JSON 직접 조회 | 0 | 96 | 0 | 260 |
| 공통 JSON 추출본 | 0 | 96 | 28 | 260 |
| RDF 하이브리드 | 0 | 96 | 28 | 260 |

정상 갱신은 네 비교군 합계 3,072행에서 모두 일치했다. JSON 추출본과 RDF 하이브리드는 정상·오류 주입을 합친 3,072개 대응에서 결정·값과 근거가 모두 같았다. 이 일치는 두 조건이 모두 맞았다는 뜻이 아니다. 두 추출본이 같은 오래된 정보를 읽으면 함께 틀렸다.

설정 지연은 업무별 JSON에서는 한 업무의 사본, 공통 조건에서는 세 업무가 공유하는 사본에 주입했다. 따라서 32와 96을 보고 업무별 JSON이 세 배 안전하다고 해석하지 않는다. 지연된 설정에 노출된 행도 각각 128개와 384개였다. 어떤 설정 변경은 특정 업무의 출력에 영향을 주지 않는다.

추출본 지연에서는 현재 원천 또는 매핑과 버전이 다른 행이 각 추출본 조건에서 384개였지만 결정·값 오류는 28개였다. 예를 들어 필드명만 바뀌었고 정규화된 값은 같다면 이전 추출본으로도 같은 답이 나올 수 있다. 버전 불일치와 실제 오답을 합치지 않는다. 직접 조회 조건에는 지연시킬 추출본이 없었다.

## 실제 업무 출력

아래는 제품 24개·시드 17 조건의 관측 사례다. 식별자와 국가는 모두 합성 값이다. 추천은 주어진 후보 중 허용된 최저 비용 공급자를 고르는 고정 규칙이다.

### 예비 공급자 허용과 업무 간 차이

제품 p0의 주 공급자는 s0이고 국가는 C0, 비용은 30이다. 예비 공급자 s1은 C1에 있고 비용은 10이다. 예비 공급자를 허용하면 국가 조회는 C0·C1, 추천은 s1이 되어야 한다.

| 배포 상태 | 국가 조회 | 추천 |
| --- | --- | --- |
| 정상 갱신 | C0, C1 | s1 |
| 업무별 JSON의 국가 조회 설정만 지연 | C0 | s1 |
| 공통 설정 지연 | C0 | s0 |

업무별 사본에서는 국가 조회에 없는 C1의 공급자가 추천되는 차이가 나타났다. 공통 설정은 서로 같은 이전 기준을 사용했지만 현재 기준의 답은 놓쳤다. 업무 간 일관성과 올바른 최신 기준의 적용을 따로 확인해야 하는 사례다.

### 국가 이동과 오래된 추출본

제품 p3의 공급자 s3가 C0에서 제한 국가 C2로 이동한 상태다.

| 조회 경로 | 국가 조회 | 지역 제한 점검 | 추천 |
| --- | --- | --- | --- |
| 현재 원천 직접 조회 | C2 | 차단 | 추천 불가 |
| 지연된 JSON 추출본 | C0 | 통과 | s3 |
| 지연된 RDF 추출본 | C0 | 통과 | s3 |

두 추출본은 같은 잘못된 답을 냈다. 추출본 지연 조건 전체에서 두 비교군 각각 제한 대상을 통과시킨 경우가 4개, 잘못된 추천이 12개였다. 잘못된 추천에는 비용 순위 오류도 포함되므로 전부 제한 지역 위반으로 해석하지 않는다.

### 형식에 맞는 다른 의미의 국가 필드

제품 p4는 C0의 s0와 C1의 s4에 연결된다. C1을 제한 국가에 추가한 뒤 모든 비교군이 공급 국가 대신 세금 관련 국가 필드 `tax_country`를 읽도록 잘못 매핑했다. 이 필드는 두 공급자 모두 C0이므로 값의 형식에는 문제가 없다.

네 비교군 모두 국가 C0만 반환하고 제한 점검을 통과시켰으며 s4를 추천했다. 의도한 공급 국가 기준으로는 C0·C1을 반환하고 제한 관계를 차단하며 허용 후보 s0를 추천해야 한다. 매핑 오류 조건에서 각 비교군은 제한 대상을 72번 통과시켰다.

이 경우 설치된 설정과 추출본의 버전은 일치했다. 버전 정합성은 데이터가 의도한 의미로 해석됐다는 보증이 아니다. 의도한 설정과 다른지는 평가자가 알고 있는 조건으로 판정했으며 실행기에 그 정답을 전달해 고치지 않았다.

## 해석 범위와 데이터 규모

두 제품 규모·두 시드·여덟 독립 상태·네 오류 조건·여덟 질의 대상·세 업무·네 비교군을 조합했다. 관심 제품 7개와 존재하지 않는 ID 하나는 고정이며 시드와 규모는 배경 관계만 바꾼다. 시드 17과 29의 상태별 지연 대상도 같다. 12,288행을 독립적인 기업이나 사용자 질문의 수로 해석하지 않는다.

업무별 사본은 3개이고 공통 사본은 1개다. 수정할 설정 사본 수는 구조상 줄지만 실제 사람이 덜 작업했다는 측정은 없다. 정상 조건에서는 모두 완전히 수정했으며 오류는 사전에 정한 방식으로 주입했다. 서로 다른 오류 조건을 합친 종합 순위나 실제 운영의 실패 확률은 제시하지 않는다.

선택한 필드의 의미는 같지만 직렬화 크기는 달랐다. 초기 제품 96개·시드 17에서는 원천 JSON 29,101바이트, 선택 필드 JSON 7,021바이트, RDF N-Triples 35,723바이트였다. RDF도 메타데이터를 제외했지만 이 직렬화에서는 파일 크기가 더 컸다. RDF DB 저장량이나 일반적인 압축 성능을 측정한 값은 아니다.

## 독립 대조와 실행 환경

소프트웨어 테스트 165개가 통과한 뒤 실행했다. Python 3.12.3과 RDFLib 7.6.0을 사용했으며 실행 시간은 42.64초, 클라이언트 최대 RSS는 66,436KiB였다. 시간에는 파일 기록이 포함되며 엔진 속도 비교로 사용하지 않는다.

실행기의 최종 결정 함수는 네 조건이 공유한다. 별도 분석기는 실행기 함수를 가져오지 않고 현재 원천과 의도한 설정에서 결정·값·근거를 다시 계산해 12,288행 전체의 평가 기준과 저장된 점수를 확인했다. 32개 원천 상태, 512개 배포 기록, 256개 추출본을 대조하고 RDF 파일 128개를 다시 읽었다. 버전 관련 플래그 768개도 기록된 원천·설정에서 재계산했다. 실행 전후 소스 해시는 같았다.

첫 종합 검토의 문맥 한도 실패를 보존하고 줄인 문서로 새 독립 검토를 받은 뒤 테스트와 실험을 시작했다. [검토 기록](../../lessons-learned/2026-10-14-shared-semantics-review.md)에 생략 범위와 반복 표본의 제한을 남겼다.

# 복잡도와 최소 온톨로지 개입 비교 결과

합성 제조 승인 120문항의 첫 실행을 재개분까지 완료하고 두 번째 반복에서는 69문항을 완료했다. 두 번째 응답 시간 초과 이후 남은 유료 호출을 중단했다. 실제 GLEIF 24문항은 오프라인 경로 검증까지 마쳤으며 LLM 비교와 질문 계약 추출 진단은 미실행이다. 아래 결과에는 최초 중단 뒤 재개한 응답이 포함된다.

## 실행 범위와 비용

계획은 합성 2,160행, GLEIF 192행, 계약 추출 48행이다. 합성의 논리 행은 정상 출력 1,703행·오류 1행·미실행 456행이며 최초 중단의 오류 1행은 별도 원본 이력에 보존했다. GLEIF의 모델 포함 비교 192행과 계약 추출 48행은 모두 미실행이다. 오프라인 GLEIF 점검 48행은 이 모델 비교와 구분한다. 비교군 중 사후 검사와 선택 검사는 같은 모델 응답을 재사용하므로 결과 행 수는 API 호출 수와 다르다. 이번 호출은 총 **569회**이며 응답과 비용이 확인된 567회, 응답을 받지 못한 2회를 포함한다.

확인된 API 사용액은 **$0.09230145**이고 모든 시도의 누적 예약액은 **$0.61376220**다. 미확인 2회의 실제 청구액은 확인된 사용액에 포함되지 않는다. 예약액은 실청구액이 아니며 실패한 호출도 예약액에서 제외하지 않았다. AWS와 Codex 비용은 별도다.

## 합성 제조 승인

모든 비교군의 출력이 있는 실행 묶음은 189개다. 이 묶음만 같은 분모로 비교한다. 첫 반복 120개와 두 번째 반복 69개이며 189개의 독립적인 질문은 아니다. 부분 실행된 한 문항의 코드·SHACL 결과는 원시 행에 남겼지만 아래 비교에서는 제외했다.

| 비교군 | 계약 일치 | 잘못된 긍정 | 불필요한 부정 | 불필요한 보류 |
| --- | ---: | ---: | ---: | ---: |
| 코드 규칙 | 189 / 189 | 0 | 0 | 0 |
| SHACL | 189 / 189 | 0 | 0 | 0 |
| LLM 직접 판단 | 124 / 189 | 15 | 26 | 3 |
| LLM 추가 검토 | 122 / 189 | 9 | 28 | 3 |
| 판단 전 검사 | 179 / 189 | 0 | 9 | 1 |
| 판단 후 검사 | 139 / 189 | 0 | 26 | 3 |
| 판단 후 코드 검사 | 139 / 189 | 0 | 26 | 3 |
| 깊이별 선택 | 159 / 189 | 8 | 17 | 1 |
| 조건별 선택 | 157 / 189 | 9 | 13 | 3 |


계약 일치는 제공된 근거에 선언된 규칙을 올바르게 적용했는지 뜻한다. 잘못된 긍정은 계약상 거부·보류인데 허용한 경우다. 불필요한 부정은 계약상 허용인데 거부한 경우이며 불필요한 보류와 구분했다. 근거가 없어 보류해야 하는데 거부한 경우도 계약 불일치이지만 불필요한 부정 열에는 포함하지 않는다.

제약을 만족하는 거짓 사실은 이 표의 계약 일치와 별개다. 코드와 SHACL은 각각 39회, 39회 평가 원본과 다른 허용을 했다. 정상과 거짓 사실의 보이는 입력은 계획된 각 반복의 24쌍에서 완전히 같다. 외부 반증이 없으므로 검사만으로 거짓 사실을 구분할 수 없는 구성이다. LLM의 과도한 거부가 이 조건에서 우연히 원본과 일치해도 사실 검증에 성공했다고 보지 않는다.

## 실제 질문과 응답

### 연결 질문에 섞인 허용 상태

사례 `r621fc80f083aa57e`는 두 링크 뒤의 도착점만 확인하는 질문이다. 제공된 계약에는 메타데이터를 검사하지 말라고 명시돼 있다. 경로에 있는 조직 하나의 `permitted`가 `false`지만 연결 질문의 정답은 허용이다.

| 방법 | 실제 판정 | 계약 기준 |
| --- | --- | --- |
| 코드 규칙 | 허용 | 일치 |
| SHACL | 허용 | 일치 |
| LLM 직접 판단 | 거부 | 불일치 |
| LLM 추가 검토 | 거부 | 불일치 |
| 판단 전 검사 | 거부 | 불일치 |
| 판단 후 검사 | 거부 | 불일치 |

```text
출하 대상 ── 조직 A ── 지정 조직
                │
          permitted=false

연결만 묻는 계약: 허용
허용 상태까지 묻는 계약: 거부
```

같은 기록에서 복합 조건을 요구하면 거부가 맞다. 어떤 질문 계약을 적용하는지가 먼저 결정돼야 한다. 위 차이는 모델의 내부 추론을 직접 확인한 결과는 아니다.

### 무관한 조직이 추가된 질문

같은 질문·계약·정상 경로에서 연결되지 않은 조직 8개만 추가했다. 첫 반복의 직접 판단은 `r412adce59f5720b2`에서 허용, `r107af37659072e19`에서 거부였다. 이 쌍의 올바른 판정은 둘 다 허용이다. 전체 대응 쌍의 변화 횟수는 위 표에 공개했다.

## 실제 GLEIF의 오프라인 점검

실제 RR 데이터에서 선정한 24개 질문은 Python 탐색과 실제 SPARQL 조회가 모두 24 / 24로 일치했다. 이는 고정 입력과 경로 구현을 확인한 오프라인 점검이다. 두 번째 시간 초과 뒤 전체 유료 호출을 멈췄으므로 GLEIF의 LLM·혼합 비교는 실행하지 않았다.

기존 실험과 겹치지 않는 12개 출발 기업에서 도달 가능·불가능 질문을 한 번씩 구성했다. 동일한 기업의 두 질문에는 같은 근거를 제공했다. 이 과제의 기호적 비교군은 SHACL이 아닌 SPARQL 경로 조회다. 외부 금융 사실 검증 결과로 해석하지 않는다.

SPARQL 비교군은 `ASK`로 판정하며 인용 목록을 반환하지 않았다. 인용 식별자 존재 여부만으로 근거 제시 품질을 비교할 수 없다. 깊이 4의 실제 긍정·부정 질문과 입력 관계는 [사례 JSON](20261013-hybrid-samples.json)에 보존했다.

## 자연어 질문의 계약 추출

24개 질문을 두 번 실행하는 48회 진단은 설계·구현·오프라인 테스트까지 마쳤으나 모델 호출은 수행하지 않았다. 공개 JSON에도 48행을 미실행으로 표시했다. 정답으로 작성한 계약을 모델 응답처럼 제시하지 않는다.

지원하는 계약 12개를 템플릿에 넣은 오프라인 점검은 Python과 SHACL에서 의도한 판정과 일치했다. 이것은 컴파일러 점검이며 질문을 해석하는 모델의 정확도 측정이 아니다. 유효한 형식으로 틀린 계약을 선택하면 뒤의 SHACL은 원래 질문과의 불일치를 알아내지 못한다. 이 한계는 별도로 구분했다.

## 최소 투영과 검사 비용

원천 레코드의 필드 수 중앙값은 67, RDF에 옮긴 원천 필드는 51개였다. 이름·설명 필드를 제외했으며 최소 투영을 자동으로 찾거나 객체 일부만 모델링한 실험은 아니다. 미리 고른 필드를 옮긴 구성이다.

중단·재개를 포함한 191회 검사에서 Python 검사 시간 중앙값은 0.083ms, RDF 투영과 SHACL 검사를 포함한 함수 시간은 154.867ms였다. 모델 호출 시간과 별도로 측정한 값이며 전체 서비스나 그래프 DB의 성능 비교가 아니다. JSON 크기 중앙값은 2235바이트, Turtle은 2008바이트였다. RDF 전환이 저장 용량 절감을 뜻하지는 않는다.

Python과 SHACL의 사전 보고서 입력은 120문항 모두에서 같았다. 따라서 판단 전 보고서의 효과를 RDF만의 이점으로 분리할 수 없다. Python 보고서를 넣은 별도 모델 호출은 실행하지 않았다.

## 중단 기록과 민감도 분석

첫 실행에서 72문항의 216회 응답 이후 한 요청의 응답을 받지 못했다. 원래 예외 종류는 저장되지 않아 시간 초과였다고 단정할 수 없다. 원본 실행의 오류·미실행 행을 유지하고 48개 미완료 문항만 새 실행으로 이어갔다. 같은 문항의 첫 검사 전 호출을 한 번 다시 시도한 이력을 별도로 표시했다.

두 번째 반복의 208번째 요청은 `ReadTimeout`으로 약 60초 후 실패했다. 이에 남은 합성 문항, GLEIF 모델 비교, 계약 추출의 유료 호출을 모두 중단했다.

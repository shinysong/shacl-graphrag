# Evidence-only report attachment

D stores the exact original C envelope as its evidence field and adds a separate
report from the unchanged Python check_evidence function. No source corpus,
question interpretation, reference answers or retriever is supplied to that
function. This is generic selected-record checking, not a native SHACL engine.

```text
Saved C envelope -> unchanged evidence field in D
                -> pure checker -> separate report with selected evidence IDs
```

The wrapper verifies nonmutation, report/evidence hash binding, selected-only
citations and a32000-byte report cap. Failed C retrieval is retained as failed
input; checker returns an error receipt with no successful results. Report
attachment success means serialization completed, not checker success, conformance,
question completeness or factual truth. No global pass, veto, filter or repair.

Record original E5 accounting tokens for source evidence, report and exact combined
JSON separately, with combined bytes. These counts are not additive because of
serialization/tokenization. Source evidence remains unchanged even if the added
report makes the combined payload exceed4096tokens. No generator runs here and
no equal-total-generator-budget comparison is claimed. A later generation study
must declare a shared total budget and reserve report allowance across arms before
execution; truncating C only in D would break this evidence identity condition.

The runner reads only saved C, pinned tokenizer and hash-bound code/policy metadata.
The checker-call boundary has software tests blocking Python file/network reads;
this is not OS-enforced isolation. Frozen24question universe includes faileddev017.
All attachment failures and missing executions count against24. Freeze manifests,
source envelopes and checker code; preserve failures and never silently rerun.

Consumed development support results remain A0/B1/C7/E7 out of18 present cases,
with6bundle-absent references. D has exactlyC source evidence by construction,
not an independently measured answer or support improvement. Rule-report usefulness
for a model, unnecessary withholding and answer accuracy remain unmeasured.

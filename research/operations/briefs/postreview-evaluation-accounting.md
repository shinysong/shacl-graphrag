# Offline post-answer evaluation accounting

Review scripts/postreview_evaluation.py and tests/test_postreview_evaluation.py. No paid calls or model outcomes. Coordinator implements accounting only; externally supplied per-primary-target annotations are not automatic scoring or expert validation. Rubric axes are from research/post-answer-review-1/evaluation-design-001/rubric.json. Do not read reference targets, historical raw QA or other reviewers.

Plan: after both independent approvals, run the seven unittest methods and save one authored two-workflow accounting example using test fixture. This is software verification only. No model rank, accuracy inference, human consensus, new source or runtime gold. Keep every planned draft/self_review/report state; unsuccessful outputs cannot have success payload or annotations; failed draft blocks dependent revisions. Self-review is independent of report failure. Labels hash-bound to successful payload; rationale is audit material, not correctness assurance. Unknown labels remain unknown. Count separate axes and paired target transitions; wrong-to-withheld is not improvement. Missing annotations remain unscored. Annotator identifiers are operator annotations, not identity authentication. All outputs remain immutable input.

Current limitations: no provider runner or schema validator, no source-witness or literal answer-span verification, no automatic correctness/expert labels, no blinded packet generator. External annotations can be semantically inconsistent; retain them rather than silently repair. Evaluator references/support eligibility never reach runtime. Test fixture labels are expressly authored synthetic software cases. Hash binding is content integrity, not authenticity.
